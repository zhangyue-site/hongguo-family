# 手机端交互问题分析（用户指出：冷启直接进播放，不像"短视频+长剧结合"的软件）

## 现状行为（0.3.x 的真实流程）
1. 冷启 → catalog 数据回来 → feedCatalog() 判定 autoStart（首次、未播放过）→ **flipTo(0) 直接拉第一部的集数并开播**
2. FeedView 的 onFeedSettled：只要"正在播"，用户上下滑翻到新页就自动 flipTo 播新剧
3. 信息层（标题/全N集/收藏/选集）只是贴在播放画面上的 overlay

## 问题定性（对照抖音/红果手机版）
- 抖音/红果手机版：首页 feed 是**海报浏览层**——上下滑看的是"选剧"，画面是静态海报+剧名+看点文案；用户**点击海报或"播放"**才进播放器；播放器内上下滑才是"下一部/上一部"
- 我们现状：feed 页=播放器页，冷启即播（无声循环加载），等于把"选剧"这层砍掉了
- 短剧特殊性：单集 1-2 分钟，但"剧"仍是选剧决策单位——上来就随机播第 1 集浪费流量也无决策感；且续播历史会乱跳

## 正确形态（三层）
1. **浏览层（冷启默认）**：全屏海报 feed——海报大图 + 剧名 + 题材标签 + 集数 + 一句话看点；上下滑翻剧；底部"▶ 立即播放"大按钮 + "选集"入口；顶部 feed 顶栏保持（推荐/收藏/历史/搜索/分类/设置）
2. **播放层（点播放后）**：现有引擎全屏播放；播放内上下滑=上一部/下一部（保留现状 onFeedSettled→flipTo）；左右/点按=集内进度与控制
3. **从播放回浏览**：BACK 退出播放回到浏览层，停留在刚才那部（不是回到冷启位置）

## 实施要点（FeedActivity 改造，0.3.5）
- flipTo(index) 拆两段：previewAt(index)=只拉海报与元数据填充浏览页（不播）；playAt(index)=现在 flipTo 的开播逻辑
- feedCatalog 的 autoStart 改为 previewAt(0)，永不自动开播
- onFeedSettled：未播放时只 previewAt(newIndex)；播放中翻页才 flipTo（保留）
- buildPage 的 info 层改为浏览层主体：海报 ImageView（loadCover）+ "▶ 立即播放"（playAt）+ 选集/收藏
- 播放中 BACK：stopPlayer 后留在当前 index 的浏览页（现状回 feed 已如此，核对焦点与页码即可）
- 续播历史入口：历史 tab 保持直接进该部"播放层"（历史语义就是继续看）

## TV 瀑布流（并行进行）

- 播放层同样受益：TV 遥控上下键=播放内上一部/下一部（短剧特性，用户点名）
